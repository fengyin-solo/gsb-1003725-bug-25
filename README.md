# 水文监测站网管理系统

面向水文监测站点运行、水位流量雨量数据采集、遥测设备维护与数据整编发布的水文站网管理平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `hydrology-monitor-station:entries` 这一项，或调用 `resetModule(模块)`。

## 水质检测状态机

水质检测的读写不走通用动作跳转器，而是走 `src/api/water-quality.ts` 领域服务（纯函数，可单测）：

```text
已采样 ──开始检测──▶ 检测中 ──出具报告──▶ 待复核 ──复核通过──▶ 已复核
                                       │
                                       └──复核退回──▶ 退回 ──重新提交──▶ 待复核
```

- 「超标/达标」是**检测结论**而不是状态，只在出报告时由「检测值 vs 标准上限」服务端判定，
  任何入口都不能手工写结论；动作必须命中显式状态机的前置状态，不能再从检测中跳到已复核。
- 两个检测入口（列表「出具报告」、页头「登记水质检测报告」）走同一个落库函数，登记成功即写入
  「待复核」待办；看板的待办只统计「待复核」。
- 复核权限：**复核员、主管**可复核；检测员只能检测/出报告/重新提交；所有写操作限本单位，
  跨单位直接拒绝（页头可切换演示身份与单位）。
- 旧报告兼容：旧状态「已出报告/超标」读取时自动迁到「待复核」，旧「已复核」报告原样保留。
- 退回只清复核人/复核时间/复核意见等复核产物，检测结论作为报告事实保留；再次提交沿用已有值，
  改了检测值才重算，payload 里伪造结论不会被采信。
- 并发：每行带 `_version` 乐观锁，先落库的结论生效，后到的提交落败并清空 `_pending*` 中间字段；
  多标签页通过 `storage` 事件让缓存失效。
- 测试：`cd frontend && npm test`（领域纯函数 + local-service 集成，node:test，无需额外依赖）。
